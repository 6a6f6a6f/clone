# Clone modernization and macOS delivery plan

Status: implementation is in stacked draft PRs; distribution acceptance and merge review remain outstanding.
Reviewed on September 8, 2026, against commit `662d4c2123f01d61ea8c98128abedc5b9cb505e6`.

Implementation uses Homebrew Cask for prebuilt archives, avoiding formula source-build prerequisites. CI/CD remains paused; see [distribution operations](MACOS_DISTRIBUTION.md).

Published backlog: [tracking issue #1](https://github.com/6a6f6a6f/clone/issues/1), with links to all 22 task issues and their dependencies.

## Outcome and scope

Deliver a small, dependable CLI that organizes Git clones, handles hostile input safely, and is straightforward to install, update, and remove on macOS. Keep C# and Native AOT: the current problems do not justify a language rewrite or a GUI. The application has no explicit third-party runtime NuGet package references; it does depend on an external Git executable and operating-system facilities.

The first delivery targets macOS on Apple Silicon only (`osx-arm64`). Intel Macs are out of scope. Advertise support only after testing the native artifact. Define the minimum supported macOS version from the selected .NET, packaging, and test environments. Windows and Linux installer work is deferred; preserve existing source compatibility where practical without claiming those platforms are validated.

Use Homebrew as the primary developer installation channel and a signed, notarized `.pkg` for users without Homebrew. A custom download-and-execute shell installer is unnecessary for the first release. Normal cloning must not require administrator privileges. Installation and updates must preserve cloned repositories and user configuration.

These probes establish source behavior under .NET 10; they do not validate the original .NET 9 build, Native AOT publication, real remote authentication, or installers.

### Reproduced examples

The parser returned success for all of the following:

| Input | Parsed result or observed behavior |
| --- | --- |
| `https://github.com/../sample.git` | Owner `..`; destination `/safe/projects/../sample`. |
| `git@example.com:/tmp/owner/sample.git` | Owner `/tmp/owner`; destination `/tmp/owner/sample`, outside `/safe/projects`. |
| `ssh://git@example.com/team/repo.git` | Owner `//git@example.com/team`; the rooted component replaces the intended root. |
| `https://github.com/team/` | Empty repository name. |
| `https://example.com/team/subgroup/repo.git` | Owner becomes only `subgroup`, losing the parent namespace. |
| `https://example.com/team/sample.git --quiet` | The subprocess received `--quiet` as a separate option. |

With an isolated Git stub and a root named `projects with spaces`, the destination was split into three arguments. The stub exited 128; the CLI printed success and returned 0. A second harmless stub in the current directory printed `CWD_EXECUTABLE_SELECTED`, confirming executable shadowing. No network clone or hostile payload execution was needed.

## Security model

The protected assets are local files, existing repositories, credentials managed by Git/SSH, the integrity of the invoked executable, and distributed binaries. Trust boundaries are CLI input to Git arguments, remote identity to filesystem paths, current directory/PATH to executable selection, Git output to terminal/logs, and build artifacts to installed software.

Assume copied URLs, remote server messages, directory entries, and downloaded artifacts may be hostile. Git configuration, credential helpers, and SSH configuration can execute user-configured programs: preserve deliberate user authentication workflows, document this local trust boundary, and do not claim to sandbox a compromised account or a malicious Git binary.

There is no application server, tenant model, or application login in this codebase. Authentication stays with Git/SSH and authorization with the remote hosting service plus local filesystem permissions. Do not add token storage, bypass host-key checks, disable TLS verification, or execute setup commands from cloned repositories.

Controls below cover executable spoofing, argument/path tampering, trustworthy exit results, credential disclosure, stalled processes/output exhaustion, unintended execution with local privileges, and escape into adjacent directories. Running the CLI as root is outside the normal supported workflow.

## Prioritized task list

P0 blocks a safe release. P1 is required for the intended macOS user experience. P2 can follow the first validated macOS release. Every task should become a focused change with its own relevant tests; estimates are relative: S = small, M = moderate, L = substantial.

### Milestone 1: safe, testable core

- [ ] **T01 — chore(build): migrate to .NET 10 LTS** — P0, M. Align `global.json`, both target frameworks, CI, and local scripts on a serviced .NET 10 SDK. Consolidate shared properties, remove duplicate `EnableUnsafeReflection`, keep executable publication settings in the executable project, and replace the legacy formatter tool with SDK `dotnet format`. Avoid unrelated solution-format changes. **Accept:** clean restore/build and formatting pass; AOT/trim diagnostics are reviewed; a macOS AOT smoke build passes. **Depends on:** none.

- [ ] **T02 — fix(process): preserve argument boundaries** — P0, S. Populate `ProcessStartInfo.ArgumentList`; retain `UseShellExecute=false`; put `--` before the validated remote and destination in the Git clone invocation. Never accept a free-form string of extra Git options. **Accept:** a recording subprocess receives exactly the intended arguments for spaces, quotes, Unicode, and option-like input; unsupported input is rejected before launch. **Depends on:** T01 for the maintained test baseline.

- [ ] **T03 — fix(remote): validate supported Git remote formats** — P0, M. Introduce a typed remote identity containing transport, host, namespace segments, and repository. Support HTTPS, `ssh://`, and SCP-style SSH with nested namespaces. Define host/port and SSH alias handling. Reject empty names, dot segments, control characters, malformed encodings, ambiguous separators, and credential-bearing HTTPS userinfo. Handle percent encoding consistently without decoding separators into paths. Apply bounded input lengths. **Accept:** table-driven valid and hostile cases; equivalent supported forms map consistently; parsing alone never creates directories. **Depends on:** T01.

- [ ] **T04 — fix(storage): confine clone writes and cleanup** — P0, L. Validate the root and all destination components, enforce containment with a filesystem-aware symlink policy, and avoid relying on a textual path-prefix check alone. Clone into an exclusively created staging directory on the destination filesystem; publish without replacing an existing destination. Track directories owned by this invocation, use `finally`, and reject unsafe symlink/race states. Never recursively delete user-owned data during failure recovery. **Accept:** traversal, rooted components, symlink escapes, concurrent clones, existing files/directories, read-only storage, and failed clones preserve sentinel files inside and outside the root. **Depends on:** T02, T03, T06.

- [ ] **T05 — fix(git): resolve a trusted executable deterministically** — P0, M. Stop implicit lookup in the current directory. Resolve eligible absolute PATH entries in order, skip empty/relative entries, check executability, and retain the selected absolute path. Allow an explicit absolute Git override. Support legitimate multiple Git installations and diagnose missing Git or Command Line Tools without silently installing them. **Accept:** a current-directory `git` is never selected implicitly; Apple Git and Homebrew Git coexist; a missing/unusable Git gives actionable output. **Depends on:** T01.

- [ ] **T06 — fix(process): report failures and cancel cleanly** — P0, M. Return a structured process result with exit status; make orchestration async end to end. Separate stdout/stderr, dispose processes, drain streams, connect Ctrl-C, and distinguish startup failure, nonzero exit, timeout, and cancellation. Terminate owned descendants and await their exit. Replace the unconditional 60-second deadline with a documented configurable policy suitable for large clones. **Accept:** Git exit 128 yields CLI failure; success requires exit 0 and the expected repository; timeout/cancel leave no owned child running; normal progress on stderr does not imply failure. **Depends on:** T01.

- [ ] **T07 — fix(security): protect credentials and terminal output** — P0, M. Reject embedded HTTPS secrets before invocation, delegate authentication to existing Git/SSH helpers, sanitize untrusted terminal controls, redact sensitive URL material from errors, and bound retained diagnostics. Preserve useful progress without buffering the entire output. **Accept:** synthetic tokens and escape sequences do not appear unsafely in stdout, stderr, structured output, or exception diagnostics; high-volume output uses bounded retained memory. **Depends on:** T03, T06.

- [ ] **T08 — fix(security): restrict implicit Git transports** — P0, M. Define HTTPS/SSH as the initial remote transport policy. Reject implicit local paths, `file`, unauthenticated HTTP/Git transports, and external helper syntax unless a later explicit feature designs their separate trust rules. Enforce the policy at Git invocation as well as parsing, considering URL rewrites. Review inherited environment, templates, hooks, filters, and helper behavior without indiscriminately removing required SSH-agent or credential-helper settings. **Accept:** direct internal API calls cannot bypass validation; protocol rewrites cannot activate forbidden transports; normal approved HTTPS/SSH authentication still works without weakening verification. **Depends on:** T02, T03, T05, T06.

- [ ] **T09 — test(core): cover security and clone lifecycle regressions** — P0, M. Add focused unit and integration projects around parsing, destination ownership, and the process adapter. Persist the regression scenarios from this review, use recording subprocesses, and add deterministic Git fixtures in temporary directories with isolated config. Keep test-only local transport settings out of production policy. **Accept:** each F01–F04 reproduction fails against the old behavior and passes after its fix; real Git success/failure and cleanup are covered without internet or personal credentials. **Depends on:** T02–T08.

### Milestone 2: usable command-line behavior

- [ ] **T10 — feat(cli): provide help and predictable command results** — P1, M. Add `--help`, `--version`, concise examples, explicit option errors, and documented exit codes. Fix the incorrect `Router` name. Keep `clone <remote>` as the shortest path. Keep parsing separate from application behavior and add a CLI library only if its maintenance, license, and AOT compatibility justify it. **Accept:** first-time users can discover syntax without a web search; help/version work without Git, configuration, or network; errors do not expose stack traces by default. **Depends on:** T01, T06.

- [ ] **T11 — feat(config): make first use work without shell setup** — P1, M. Recommend `~/Projects` as the default; preserve `CLONE_PROJECT_FOLDER`; define precedence as CLI override, environment, persisted configuration, then default. Introduce a small configuration command and choose/document a macOS-appropriate config location. Show the resolved destination and create a missing root safely on the first clone. **Accept:** clean-shell first clone needs no profile edit; paths with spaces work; invalid or unwritable configuration produces a recovery instruction; configuration never stores secrets. **Depends on:** T03, T04, T10.

- [ ] **T12 — feat(storage): distinguish hosts and preserve existing layouts** — P1, M. Define a collision-resistant `root/host/namespace/repository` layout for new configurations, including port/alias rules and macOS case/Unicode behavior. Preserve existing `owner/repository` installations through an explicit compatibility setting; provide a preview for any future migration and never move existing clones implicitly. Show the existing path and whether its origin matches on collision, with secrets redacted. **Accept:** two hosts and nested GitLab-style groups remain distinct; existing clones are preserved; mismatched origins are never silently reused or updated. **Depends on:** T03, T04, T07, T11.

- [ ] **T13 — feat(cli): support terminals and automation cleanly** — P1, M. Send progress and diagnostics to stderr and reserve stdout for the successful destination. Respect redirected output and `NO_COLOR`; add quiet behavior and explain Ctrl-C and timeout recovery. Explicitly handle noninteractive authentication so scripts cannot hang on hidden prompts. **Accept:** pipes contain no ANSI decoration or progress; exit codes match outcomes; interactive SSH/HTTPS prompts remain usable; cancellation reports what remains on disk. **Depends on:** T06, T07, T10.

- [ ] **T14 — feat(cli): diagnose setup and preview destinations** — P2, S. Add a read-only `doctor` command for version, architecture, Git path/version, root/config source, and filesystem problems; add a no-network destination preview and zsh completion. Avoid printing raw environment variables or credentials. **Accept:** diagnostics explain common setup failures, preview does not create directories, and completion works in a fresh zsh session. **Depends on:** T05, T10–T13.

### Milestone 3: automated macOS distribution

- [ ] **T15 — build(macos): produce explicit native release artifacts** — P0 release gate, M. Publish `Release` with the explicit `osx-arm64` RID in supported native Apple Silicon macOS build environments. Set a stable executable name, version from a validated tag, and deterministic output directories. Record the minimum OS and architecture in versioned archive names; keep debug symbols separate. Validate the native binary's system-library dependencies. **Accept:** each advertised artifact executes on its matching architecture without an installed .NET runtime; version and tag agree; archives preserve executable permissions. **Depends on:** T01, T09, T10.

- [ ] **T16 — ci(security): gate and harden release publication** — P0 release gate, M. Add PR CI for build, format verification, meaningful tests, AOT smoke publication, and workflow validation. Use reviewed current action revisions pinned by full SHA with automated update proposals. Give build jobs read-only permissions and grant publication/signing/provenance privileges only where necessary. Keep untrusted PR code away from release credentials. Fix tag propagation and shell assumptions, validate and quote tags, and remove unnecessary package installation on runners. Assemble and verify a draft release before publishing; prevent replacement of published assets. Generate archive checksums and build provenance. **Accept:** a failed check prevents publication, tags match tested commits, all assets exist before visibility, and provenance/checksum verification succeeds for the exact distributed files. **Depends on:** T09, T15.

- [ ] **T17 — build(macos): sign and notarize distribution artifacts** — P1 release gate, L. Sign executables with Developer ID Application, appropriate hardened-runtime settings and timestamp; sign installer packages with Developer ID Installer. Notarize using `notarytool`, staple supported containers such as `.pkg`, and validate the final downloadable package. Keep signing material in protected CI secrets and an ephemeral keychain with cleanup. Checksums must describe the final signed/notarized files. **Accept:** native signatures validate and a quarantined download installs/runs on a clean supported Mac without disabling Gatekeeper. **Depends on:** T15, T16; external prerequisite: Apple Developer membership and signing/notarization credentials, availability not verified in this review.

- [ ] **T18 — feat(install): distribute through a Homebrew tap** — P1, M. Create a project-owned tap using the package type appropriate to the chosen source/binary delivery model. Supply prebuilt native artifacts so users need no .NET SDK; use immutable version URLs and SHA-256 verification, an Apple Silicon architecture requirement, the Git prerequisite, and a smoke test. Document the exact tap-qualified install command, upgrade, and uninstall. Update tap metadata only after a verified release is available; use narrowly scoped publication credentials. **Accept:** clean install, upgrade, reinstall, and uninstall work on Apple Silicon; removal preserves configuration and repositories. **Depends on:** T15–T17, T21.

- [ ] **T19 — feat(install): provide a signed macOS package** — P1, L. Generate a versioned `.pkg` with a stable package identifier and a documented installation location. Keep its prefix separate from Homebrew-managed files; detect existing installations and executable name collisions. Prefer a static payload without privileged network downloads or shell-profile edits. Provide Terminal and GUI installation instructions plus an uninstall command/helper scoped to package-owned files. State clearly when system installation requires administrator approval. **Accept:** GUI and `installer` installation, upgrade, interrupted-install recovery, and uninstall preserve repositories; the binary is discoverable in a fresh standard shell; Homebrew and package ownership do not overwrite each other. **Depends on:** T15–T17, T21.

- [ ] **T20 — test(macos): validate the complete installed experience** — P1 release gate, L. Test the actual downloadable Homebrew and `.pkg` paths on clean macOS environments, on Apple Silicon, including the minimum OS. Exercise installation without .NET, missing Git, first clone, a controlled authenticated repository, spaces/Unicode, destination conflicts, offline failures, Ctrl-C, upgrade, uninstall, quarantine, and tampered downloads. Never use personal credentials in test logs. **Accept:** all supported platform/channel combinations have recorded pass evidence; bad hashes/signatures are rejected; an unsuccessful update leaves the previous installation usable; no application installer requires users to disable platform protections. **Depends on:** T09–T13, T17–T19, T21.

## Recommended execution order and release gate

Start with T01 and the core fixes T02–T08, adding regression coverage as each fix lands and completing T09. Implement T10–T13 next. Establish T15–T16 before issuing a new release, then finish T17–T19 and T21, and run T20 against the final artifacts. T22 establishes ongoing maintenance. T14 is optional follow-up polish.

The first macOS release is ready only when all P0 and P1 acceptance criteria have evidence, including installed native behavior. A passing managed build does not substitute for AOT, real authentication, signing, notarization, or installer testing. If Apple credentials or an architecture-specific validation host are unavailable, record that distribution gate as outstanding rather than calling it complete.

Keep repository management beyond cloning, GUI work, background self-updates, bundled Git, and Windows/Linux installers outside this first scope. Let Homebrew or the package workflow own updates rather than introducing an additional updater and trust path.

## Current upstream references

- **Runtime support:** .NET 9 is still supported but in maintenance, ending November 10, 2026; .NET 10 LTS support runs through November 14, 2028. This supports prioritizing the LTS migration rather than labeling .NET 9 already unsupported. [Microsoft support policy](https://dotnet.microsoft.com/en-us/platform/support/policy).
- **Native packaging:** verify target-platform restrictions and build prerequisites for Native AOT before declaring architecture support. [Microsoft Native AOT overview](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/).
- **Argument handling:** `ArgumentList` handles argument escaping; application validation and an option terminator remain separate responsibilities. [Microsoft ProcessStartInfo.ArgumentList](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.argumentlist?view=net-10.0).
- **Git trust boundary:** use the documented remote grammar and review protocol/configuration controls, including external helpers. [git-clone](https://git-scm.com/docs/git-clone), [git-config](https://git-scm.com/docs/git-config).
- **macOS distribution:** use the required certificate types, hardened runtime, timestamp, and notarization workflow; test the final distribution container. [Apple notarization requirements](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), [Developer ID certificates](https://developer.apple.com/help/account/certificates/create-developer-id-certificates/), [Apple distribution workflow](https://developer.apple.com/developer-id/).
- **Homebrew:** choose the appropriate package model and declare architecture, dependency, and checksum metadata. [Adding software](https://docs.brew.sh/Adding-Software-to-Homebrew), [Formula Cookbook](https://docs.brew.sh/Formula-Cookbook), [Cask Cookbook](https://docs.brew.sh/Cask-Cookbook).
- **Release integrity:** separate permissions and trusted publication from PR execution; pin actions and verify artifact provenance. [GitHub secure-use reference](https://docs.github.com/en/actions/reference/security/secure-use), [Artifact attestations](https://docs.github.com/en/enterprise-cloud%40latest/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations).
